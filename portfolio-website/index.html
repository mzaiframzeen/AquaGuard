LET’S CLEAR THINGS UP

A few things
worth knowing.

Is Aqua Guard monitoring real pipes today?

Aqua Guard is a student project concept. This site demonstrates the experience using simulated readings, example crews and a browser-based repair workflow. It is not connected to live utility infrastructure.

Do we need physical sensors for the prototype?

No. The planned Go simulator supplies virtual pressure readings through MQTT. A real deployment would need physical sensors, calibrated detection models and engineering validation.

Why analyse pressure between 1 AM and 4 AM?

The project focuses on a quieter demand window to explore pressure anomalies. A pressure drop is a signal to investigate, not proof of a burst. Demand is not assumed to be zero.

How are repair crews guided to a leak?

The intended backend assigns a ticket to the nearest available crew. The field app would provide GPS directions. Try the demo to open an illustrative destination in Google Maps. No real crew is contacted.

Can field workers use the app offline?

The planned Flutter app uses SQLite to keep assigned jobs and repair updates on the device, then sync when connectivity returns. This website previews that product concept; the production mobile and backend services are separate implementation work.
